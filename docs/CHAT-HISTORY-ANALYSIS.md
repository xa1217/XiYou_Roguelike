## 2. 指令层级：什么现在生效

4. **聊天中明确的产品需求与后续裁决**：仅在不违反以上三项时继承；发生冲突时采用较新的、已写入当前契约的裁决。

## 3. 原始游戏需求（从用户消息归并）

### 3.1 产品定位与循环

- 原始主会话要求从最新项目复制出独立副本，补齐原稿没有写明的部分，持续推进到可运行/可交付，并给出完整报告；这说明交付目标，不会覆盖当前分支、证据和权限边界。
- 作品是以《弹壳特攻队》类生存割草为参考的西游题材肉鸽游戏，围绕《西游记》九九八十一难推进。
- 关卡按原著的难次、地点、妖怪和首领组织；原著中没有战斗妖首的磨难保留难名和地点，并明确标注为原创心魔幻境/护行守关演绎，不伪造原著事实。
- 通过击杀妖怪获得经验；升级时暂停并出现三张候选牌，玩家选择本命武器或法宝。
- 单局最多五个技能槽：一个当前角色本命武器，加四个随机法宝；技能等级上限为五级。
- 每关原始目标时长为十分钟，刷怪频率随时间提升；精英怪按时间点出现；普通怪、精英怪和 Boss 的生命/伤害随时间成长。
- 需要移动端友好的触摸、键盘兼容、DPR/安全区、暂停恢复、后台冻结、资源清理、对象池和数量上限；角色和效果必须是可动的运行时表现，不能只摆放静态精致图片。

### 3.2 四名角色与本命武器

- **孙悟空**：金箍棒前方扇形攻击，基础间隔 1 秒；升级减少间隔并强化重击。当前裁决采用第 3 级重击为 2 倍伤害/原范围，第 4 级为 2.5 倍/1.5 倍范围，第 5 级为 3 倍/2 倍范围，第 5 级重击独立有 30% 眩晕概率。
- **唐三藏**：九环禅杖发射蓝色经文/光球，远程直线伤害；升级增加停留、持续伤害、分散和弹射等表现。当前网页切片先保证可读的远程本命攻击，不把历史绿皮书中尚未批准的辅助/治疗路线当作当前必做项。
- **猪八戒**：九齿钉耙宽直线夯击并施加流血；升级提高宽度、流血比例并引出火鸟，最高级火鸟落地产生范围爆炸。
- **沙悟净**：降妖宝杖旋转造成环形伤害；升级缩短间隔并生成水泥沙漩涡，提供持续伤害、吸附和减速。当前裁决明确第 3 级漩涡持续 1.5 秒；第 4/5 级总伤害分别按武器伤害的 8%/12% 实现，不能把同一段原稿中的“三秒”误当作第 3 级持续时间。

### 3.3 八件法宝

法宝原始清单为：七十二变、如来神掌、念力佛珠、紫金葫芦、搬山诀、芭蕉扇、风火轮、乾坤圈。需求要点是：

- 七十二变召唤持棍小猴拦截敌人；等级提高数量、拦截次数和伤害。
- 如来神掌从天而降打击指定方向；等级提高数量、范围和伤害。
- 念力佛珠环绕旋转；等级提高数量和速度，最高级可转为骷髅表现。
- 紫金葫芦扇形吸附：普通怪可被吸入秒杀，精英和 Boss 受到持续吸附伤害并减速。
- 搬山诀召唤大山落地造成范围伤害。
- 芭蕉扇造成扇形伤害和击退；普通怪、精英和 Boss 的击退强度不同。
- 风火轮直线飞行并留下持续燃烧印记；等级提高数量、宽度和燃烧时长。
- 乾坤圈追击最近敌人并反弹；等级提高反弹次数、目标数和分裂数量。

### 3.4 视觉、地图和声音

- 用户要求整体采用明快、夸张、易读的 Q 版防守游戏观感，并要求角色、妖怪、攻击、受击、Boss 入场和 UI 都有动画反馈；当前工程边界是原创资源和原创演绎，不复制外部作品素材。
- 第一关为《西游记》双叉岭：高峻山体/山林位于屏幕四周，中部山脊把地图组织成上下两个可往返区域，中央保留宽阔战斗平地和可通行小径；地图应体现山体规模而不破坏割草战斗空间。
- 第一关最终妖王为寅将军、熊山君、特处士；约五分钟出现虎先锋类精英，普通怪以三名妖王和双叉岭动物特性演绎。
- 需要 BGM、普攻/命中/升级/Boss/受击/死亡/UI 音效，以及静音开关；音频和视觉均须经过当前浏览器证据验证。

### 3.5 平台目标的演进

原始需求把作品定位为微信小游戏并希望补齐可商用能力；后续用户明确把优先级改为“先做到网页端真实测试，之后开公网通道，微信实机不着急”。因此当前工作顺序是：

1. 网页 Canvas 主线和真实 Edge 验收；
2. 公网临时测试通道和静态资源/路径隔离；
3. 微信工程结构、平台桩和发布包保持可检查；
4. 有 AppID、开发者工具和真实设备后，再做微信真机、登录、云存档、广告、分享、支付和审核。

聊天里同时存在旧绿皮书、重复原稿和新的网页切片工作。当前采用下列裁决：

| 冲突/旧说法 | 当前裁决 |

## 5. 当前范围、延期项与继续推进方式

### 当前范围

- 网页 Canvas 可启动主线、四角色、本命武器、八法宝、五级技能、三选一、五技能槽、十分钟关卡、刷怪/精英/Boss 规则、暂停/恢复、存档/经脉/每日目标、对象池/渲染剔除、原创地图和动画音频。
- `npm test`、平台桩、Node 生产步长回归和真实 Edge 浏览器 smoke 必须重新运行并记录；浏览器截图、网络访问和发布 ZIP 只引用本轮生成的证据。
- 公网通道是临时测试手段，不等于商用部署；外部传输失败应记录为失败或通道限制，不改写成 PASS。

### 明确延期

- 微信 AppID 配置、开发者工具编译预览、低端 Android/iOS 真机 FPS/内存/触摸/资源解码。
- 微信登录、云存档、广告、分享统计、支付、商用账号、审核和正式发布。
- 协作平台的共享工作区、Android companion、GitHub 登录、录音/附件和手机公网网关；这些属于附件第 29–44 会话的另一产品方向。

### 继续推进的门禁

1. 先完成当前代码的 `npm test` 和平台桩回归。
2. 串行重跑真实 Edge 的动画、视觉、音频和公网 smoke；每次输出都写入 `evidence/current/`。
3. 若公网通道仍因 QUIC/TLS/传输限制失败，保留真实失败 JSON，并以本地真实浏览器证据说明可验证部分。
4. 重新生成发布 ZIP，核对 SHA-256；发布包不得包含 `legacy-source/`、历史证据、密钥或本机账号配置。
5. 由根代理根据新证据更新 `STATUS.md`、`docs/REQUIREMENTS-ACCEPTANCE.md` 和最终报告；本文件只负责需求溯源。

## 6. 证据使用规则

- **PASS 的时间边界**：历史会话、`evidence/online/`、`evidence/T00/` 或 10 月 4 日未重跑的截图不能证明本轮状态；只能作为背景。
- **证据的范围边界**：Node、Canvas mock、微信 API 平台桩只能证明各自的模拟范围，不能冒充微信真机 GPU/FPS、登录或公网可用性。
- **证据的真实性**：报告应同时写命令、时间、入口、结果文件和未运行项；失败、超时、TLS/QUIC 取消都要保留。
- **需求的可追溯性**：实现/验收文档应链接回当前需求和本文件；如果新增需求与上述裁决冲突，先记录决策再修改代码，不能从历史聊天中默默恢复旧路线。

## 7. 结论

附件聊天历史支持的产品主线是“西游八十一难 + 生存割草 + 四角色本命与法宝构筑 + 十分钟关卡”。历史聊天还包含大量协作平台和旧 Unity/多人设计，不能与当前网页验收范围混为一谈。当前继续推进的唯一可靠基线是：遵守项目 `AGENTS.md`，以 `STATUS.md`/`REQUIREMENTS-ACCEPTANCE.md` 为现状，以当前新生成的浏览器/Node/发布证据为验收依据，并把微信真机和商用服务明确标为延期。
