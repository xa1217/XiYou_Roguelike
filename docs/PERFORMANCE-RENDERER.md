# Canvas renderer 性能优化与回归记录

日期：2026-10-04。写入范围：`prototype-2d/src/renderer.js`、`prototype-2d/tests/render-smoke.mjs`、本报告。

## 1. 测量范围

本轮先测修改前 renderer，再实现视野剔除和排序数组复用。测试主配置为原生页面的 **390×844 逻辑像素、DPR 2、high 画质、showHud:false**。

压力输入：220 个妖怪、300 个弹道、160 个特效、240 个灵珠，在 1800×1800 世界中按固定网格分布。玩家位于 (900,900)，不更新模拟，只调用 renderer 120 帧。压力分布及 Canvas 数字参数检查保存在 [render-smoke.mjs](../prototype-2d/tests/render-smoke.mjs)。

这是一组 **Node Canvas 桩调用计数与 JavaScript 耗时**；桩没有进行真实路径栅格化、GPU 绘制、像素填充、纹理传输或微信平台桥接。不能将表中的耗时取倒数声称游戏 FPS，也不能当作 iOS/Android 真机验收。

本轮尝试以 CUA 打开独立 `http://127.0.0.1:8088/native.html` 实页，工具返回 `Browser is not available: iab`。真实浏览器的页面渲染/生命周期压力检查由根代理独立执行；本报告只记录当前直接取得的测量。遵循 optimize-web-animations 技能先测后改，并公开实页测量在此子任务的限制。

## 2. 基线发现

修改前每帧：

- 对全部妖怪执行 `slice().sort()`，创建新的排序数组。
- 遍历并绘制全部灵珠、特效与弹道，即使它们完全位于画布之外。
- Canvas 自身会裁剪可见像素，但仍需执行 JavaScript 路径构建、样式设置、save/restore 和绘制调用。
- 地图已经按邻近相机网格绘制装饰，但其可视尺寸重新按固定 radius=18 计算；与实际玩家半径影响的 zoom 可能不同。

修改前实际跑 120 帧共 **3,720,840 次 Canvas 方法调用，即 31,007 次/帧**；首次计数桩采样 607.226ms。后续同一计数桩加 30 帧预热、在内存中恢复原完整绘制循环的对照采样为 427.954ms。耗时受 JIT、GC、主机负载和测量器影响，因此调用数是本轮主要对照指标。

## 3. 修改

### 可视范围剔除

renderer 每帧由真实 camera、zoom 和逻辑宽高维护同一个 `_view` AABB。先判断绘制包围范围是否与视野相交，再生成路径。high 与 low 画质都生效，不修改模拟中的碰撞、敌人数量、弹道运动、经验、技能或计时。

剔除保留合理的视觉范围：

| 类型 | 视觉边界处理 |
| --- | --- |
| 妖怪 | 半径之外包含首领冠、血条、眩晕标记与 hopHeight 位移；中心离开画布时仍可显示头顶内容 |
| 弹道 | 包含火鸟/钉耙形状、光球外层晕光及线宽 |
| 特效 | 包含环形、扇形、冲刺轨迹；hoe-line 额外包含完整前向 length 和 width，避免起点在屏外但末端入屏时漏画 |
| 灵珠 | 包含菱形下尖、阴影和脉冲缩放 |

包围范围有保守留白。靠近边缘但尚未入屏的对象可能多画少量；不会采用仅按对象中心剔除造成可见部分消失。

### 排序数组与诊断

`_enemyDrawList` 在构造时创建，帧间清空长度后重用；只有通过可见性判断的妖怪进入数组，再按 y 排序。比较器也复用。模拟的 `state.enemies` 原顺序完全保留。

新增复用的 `renderer.stats` 记录本帧绘制/剔除数量，便于平台压力页读取。该数据属于 renderer，不写入 simulation state。dispose 清空暂存对象引用。保留根代理已有 `showHud:false` 选项，没有重新启用 Canvas 内 HUD。

未引入 DOM 创建、默认离屏画布工厂、图片加载或额外帧循环。此次主要收益来自停止视野外路径工作；没有通过删除可见法宝动画取得结果。Sprite 离屏缓存未在未测量收益的情况下加入。

## 4. 同场景结果

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| Canvas 调用 / 120帧 | 3,720,840 | 662,160 |
| Canvas 调用 / 帧 | 31,007 | 5,518 |
| 相同计数桩 + 30帧预热，120帧耗时 | 427.954ms | 223.466ms |
| 每帧绘制妖怪 | 220 | 36 |
| 每帧绘制弹道 | 300 | 45 |
| 每帧绘制特效 | 160 | 25 |
| 每帧绘制灵珠 | 240 | 30 |

**该固定空间分布下，Canvas 方法调用减少 82.204%。** 184 个妖怪、255 个弹道、135 个特效、210 个灵珠的绘制工作被跳过；这些对象仍存在于模拟状态。

持久化测试包含坐标参数校验与断言，和仅计数采样的测量器不同；本次持久化完整压力测试采样为 115.939ms/120 帧，不能与另外的计数桩直接比较耗时。重复测试会出现正常的计时波动。

当所有对象都聚集在可见范围内时，视野剔除收益接近零；仍会绘制全部可见对象，并保留 hard caps。此结果不代表在最坏全同屏条件下减少了 82% 绘制，也不代表已达到手机 60FPS。

## 5. 已持久化的回归

运行：

```powershell
node prototype-2d/tests/render-smoke.mjs
```

实际结果 PASS：

1. 六主题 × 四角色；13 种 effects、4 种 projectiles、4 种 drops；Canvas 数字参数有限、arc 半径非负、save/restore 平衡。
2. 深冻结状态在渲染前后完全一致，原怪物排序不被改变。
3. 无 roundRect、gradient、DOM、Path2D 的精简 Canvas 桩可运行；帧中禁止 Math.random 仍通过。
4. 可见边缘对象、头顶血条/眩晕内容、起点在屏外的长 hoe-line 保留绘制；远处对象剔除。
5. 排序数组跨帧保持同一对象；dispose 清空引用并停止绘制。
6. showHud:false 无文字 HUD 调用；可切回 true。
7. DPR 2 backing store 尺寸、resize、low 画质、超大视口及可空数组项均通过。
8. 固定 220/300/160/240 压力场景，调用数稳定为 5,518/帧，低于原基线一半。

另外执行 `node --input-type=module --check` 检查 renderer 语法，PASS。`git diff --check` 在本任务限定范围内无空白问题；当前文件属于独立副本未跟踪文件，因此该命令不能替代文件语法和运行回归。

根级 `scripts/validate.mjs` 会构建派生微信文件并写 evidence，超出本子任务写入范围，由根代理在集成完成后运行。当前模块只负责绘制，不拥有 setInterval、requestAnimationFrame、全局监听器或平台音频；页面的隐藏/恢复与销毁由 NativeGame/platform 层管理，不能用 renderer 单元测试证明这些循环已经停止。

## 6. 真机剩余验证

根代理应以相同配置在 browser 实页 reload 后对照 `renderer.stats`，再在 Android/iOS 进行完整 10 分钟战斗、后台切换与结束重开。至少记录真实帧耗时 P50/P95、同屏最大对象、内存峰值、长局是否退化、视口边缘特效，以及微信开发者工具的包体检查。任何测试未实际执行时都不能标成真机 PASS。
